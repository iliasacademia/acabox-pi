## A. One-paragraph summary (what the planner most needs)

1. Acabox exposes exactly **12 model-visible relay tools on 7 SDK relay servers** (`activity`, `notification`, `mini-apps`, `knowledge`, `workspace`, `apis`, `chats`). Their zod schemas live in the agent-server process (`$A/agent-server/index.ts:230-394`); their handlers are plain `async (args) => ToolResult` closures in the Electron main process (`$A/main/controllers/AgentInfrastructureController.ts:119-385`), published on `globalThis.__hostMcpServers`. They are linked by an SSE `mcp-call` event plus a `POST /sessions/:id/mcp-result` round trip with a 120 s timeout. **All handlers are harness-neutral**; the schemas and the link are Claude-SDK-shaped.
2. Beyond the relays there are three more tool families: the **mini-app published MCP gateway** (not first-class tools; reached through two generic relay tools), **hosted stdio MCP servers** (host-owned supervisor `main/mcpHost/*`, exposed to the model as per-server SDK relays built at runtime from `tools/list`), and **connectors** (remote http/sse MCP servers passed straight to the Claude CLI, which owns connection, OAuth and status).
3. PI has its own MCP client extension (`createMcpExtension`) but it is **not a drop-in for the host-owned parts**: its stdio transport inherits the whole `process.env` by default, connects/closes per PI session, has no supervisor/backoff/queue/orphan reconcile, renames tool names (`mini-apps` becomes `mini_apps`), defaults to `codemode` exposure (tools not declared to the model), has no SSE transport, and runs OAuth as a user/host action rather than a model tool.
4. Two PI traps found in the PI source that affect how relays must be registered: (a) tool names starting with `mcp__` are treated specially by PI's tool selection (an allowlist without an `mcp__*` entry leaves `direct` custom tools **undeclared**), and (b) MCP `env`/`header` values are interpolated (`$VAR`, `${VAR}`, leading `!` runs a shell command), so Acabox secrets must be escaped.

### E2. What PI's own MCP stdio support would make redundant vs what must stay host-owned (READ from PI + INFERRED conclusions)
PI facts (READ): `$PISRC/packages/coding-agent/docs/mcp.md` L3, L62-64, L77-82, L94-102; `$PISRC/packages/mcp/src/transports/stdio.ts` L94, L152-179; `$PI/pi-coding-agent/dist/extensions/mcp/runtime.js` L51-71, `index.js` L971-1034 and L1114-1118.

- **Must stay host-owned (or be re-implemented through `createTransport`)**:
  - **Env allowlist.** `StdioTransport.start()` uses `{ ...process.env, ...options.env }` unless `inheritEnv === false` (stdio.ts:94) and `createDefaultTransport` passes only the config `env` with no `inheritEnv` (runtime.js:60-70).   - **Lifetime across turns/chats.** PI connects all enabled servers on `session_start` and closes them on `session_shutdown`.   - **Supervision:** ping health checks, jittered backoff/`failed` state, readiness deadline, per-server FIFO queue/concurrency (PI runs same-message tool calls in parallel; MCP tools registered by PI cannot set `executionMode` per server), `diagnose()` plain-language errors, stderr ring surfaced to the UI. PI only lazily reconnects on the next call and shows state in `/mcp`.
  - **Crash/orphan story:** PI kills groups only on a graceful `exit`; a SIGKILL/crash of the host orphans children, which `reconcileOrphans` (pid + start-time signature) handles.
  - **Approval:** sealed store, forced `enabled:false` registration, promote-on-enable copy+hash+probe, per-tool `enabledTools` write gate with two enforcement layers (PI equivalents exist as `toolExposure: 'hidden'` and a `tool_call` handler returning `{block:true}`, but the persisted model, Servers page and authored flow remain Acabox's).
  - **Authored-server launch shape** (Electron-as-node via `ELECTRON_RUN_AS_NODE=1`) is identical under PI.
- Conclusion (INFERRED): keep `main/mcpHost/*` untouched and expose ready hosted tools to PI as plain PI tools generated from `readyServersForAgent()` (see J). Using PI's MCP client for hosted servers would drop the guarantees above.

## I. PI facts that govern the port (READ)

1. **SDK entry points.** `createAgentSession(options)` options (`$PI/pi-coding-agent/dist/core/sdk.d.ts:10-65`): `cwd`, `agentDir` (default `~/.pi/agent`; env `PI_CODING_AGENT_DIR`, confirmed `$PISRC/packages/coding-agent/docs/environment-variables.md:81`), `modelRuntime`, `model`, `thinkingLevel`, `noTools?: 'all'|'builtin'`, `tools?: string[]`, `excludeTools?: string[]`, `customTools?: ToolDefinition[]`, `resourceLoader`, `sessionManager`, `settingsManager`. SDK sessions do **not** load the built-in codemode/tool_search/MCP extensions; add `createCodemodeExtension()`, `createToolSearchExtension()`, `createMcpExtension()` to `DefaultResourceLoader({extensionFactories})` and call `session.bindExtensions({})` (sdk.md L112-116).
2. **Custom tools.** `ToolDefinition` (`$PI/pi-coding-agent/dist/core/extensions/types.d.ts:453-519`): `name`, `label`, `description`, `promptSnippet?` (custom tools are omitted from the default system prompt's Available tools section without it), `promptGuidelines?`, `parameters` (TypeBox), `outputSchema?`, `exposure?` (default `'direct'`), `namespace?`, `annotations?`, `executionMode?: 'sequential'|'parallel'`, `execute(toolCallId, params, signal, onUpdate, ctx)`. Result type `AgentToolResult` (`$PI/pi-agent-core/dist/types.d.ts:370-392`): `{content:(TextContent|ImageContent)[], details, structuredContent?, usage?, isError?, terminate?}` so Acabox's `{content:[{type:'text',text}], isError?}` maps with `details: undefined`. Throwing also produces an error result. `defineTool`, `pi.registerTool` (late registration allowed; tools cannot be unregistered, withdraw with `exposure:'hidden'`). TypeBox 1.3.27; `Type` and `StringEnum` exported from `@earendil-works/pi-ai` (`StringEnum` exists because Google/other providers reject `anyOf`/`const` enums).
3. **PI MCP naming and exposure.** Tools are `mcp__<server>__<tool>` with every character other than letters, digits, `_` replaced by `_` (mcp.md L77; `createMcpToolName`, `dist/extensions/mcp/tools.d.ts:43-49`), shortened with a hash suffix for the 64-char provider limit. Hyphenated server ids are therefore renamed (`mini-apps` -> `mini_apps`) and names differing only by `-`/`_` collide. Default exposure is `codemode` (not declared to the model; reached via the `codemode` tool); `deferred` needs `tool_search`; `direct` declares them; `hidden` is unreachable; `toolExposure` overrides per tool with `*` patterns (mcp.md L189-232). Servers with codemode/deferred tools are listed to the model only in a system-prompt `mcp_servers` section built from the config `description`.
4. **`createMcpExtension(options)`** (`dist/extensions/mcp/index.d.ts:33-55`): `loadConfig?(ctx): LoadedMcpConfig`, `createTransport?: McpTransportFactory`, `credentials?: McpOAuthCredentialStore`, `logPath?`, `openUrl?(url)`, `updateConfig?`, `startupWaitMs?` (default 10 000, the first prompt waits only for servers with `direct` tools). `LoadedMcpConfig {servers: McpServerEntry[], autoEnableCodemode?, errors: string[], projectConfig?}`, `McpServerEntry {name, config: McpServerConfig, source, scope?: 'global'|'project'|'extension', override?}`. `McpTransportFactory = (entry, cwd, authProvider) => McpTransport`. The default `loadConfig` reads `<agentDir>/mcp.json` plus `.pi/mcp.json` **only for a trusted project** (config.d.ts; mcp.md L32). An inline extension holding the `pi` handle can also call `pi.registerMcpServer(name, config)` / `pi.unregisterMcpServer(name)` / `pi.getMcpServers()` live ("servers registered later connect right away", extensions.md L195-206), the PI equivalent of `POST /connectors`. Only `createMcpExtension`, `McpExtensionOptions`, `McpTransportFactory`, `LoadedMcpConfig`, `McpExposure`, `McpServerConfig`, `McpServerEntry`, `RegisteredMcpServer`, `McpServersChangeEvent` are exported from the package root (`dist/index.d.ts:11,31-32`); `McpServerConnection` (the state holder), `McpOAuthCredentialStore` and `signInMcpServer` are **not** exported.
5. **Config schema** (`dist/core/mcp-servers.d.ts:25-107`): `McpStdioServerConfig {type?:'stdio', command, args?, env?, cwd?, exposure?, description?, toolExposure?, enabled?, timeout?}`; `McpHttpServerConfig {type?:'http', url, headers?, oauth?: McpOAuthConfig, auth?:{provider}, ...same base}`; per-request `timeout` in seconds (default 60, progress resets). **No SSE** ("The legacy SSE transport is not supported", mcp.md L64, L79). `env`/`headers` values are interpolated by `resolveConfigValue` (`dist/core/resolve-config-value.js:116-122`): `$NAME`/`${NAME}` substituted, a leading `!` runs the rest as a shell command, `$$` and `$!` escape. Acabox's stored secrets must be escaped (`$` -> `$$`, leading `!` -> `$!`) or a token containing `$` fails/corrupts and a token starting with `!` would be executed.
6. **Per-session lifecycle.** `session_start` runs `loadConfig(ctx)` and connects every enabled server in the background; `session_shutdown` closes them all (`dist/extensions/mcp/index.js:971-1034`, `:1114-1118`). Connection state is internal; there is no exported programmatic accessor (status is available through `/mcp` output, `ctx.ui.notify`, `pi.getAllTools()` tool/namespace presence).
7. **OAuth in PI.** Sign-in is a user/host action (`/mcp login <server>`, `pi mcp login <server>`), never a model tool; PKCE, DCR/CIMD, refresh with a cross-process lock, loopback callback server; default client name `pi` (`oauth.clientName` configurable); tokens in `<agentDir>/mcp-auth.json` (0600, plaintext JSON via `AuthStorage` file backend, auth-storage.js:27,37). `openUrl` option lets the host open the system browser. A host that wants Acabox-style encrypted storage or its own button can use the exported `@earendil-works/pi-mcp/oauth` (`McpOAuthProvider`, `OAuthCallbackServer`, `authorizeMcp`, `adaptOAuthProvider`, injectable `McpOAuthStateStore`) together with a custom `createTransport` (INFERRED feasibility). Because the callback server lives for the duration of the sign-in action, not the agent session, the 5-minute pin machinery is unnecessary under PI.
8. **PI name-based tool selection trap** (`dist/core/agent-session.js:193-197,1121-1139`; `dist/core/mcp-servers.js:34-36`): `isMcpToolName(name)` = `name.startsWith('mcp__')` or a resource tool. If `createAgentSession({tools:[...]})` is given a non-empty allowlist containing no entry that starts with `mcp__`, `_allowlistFiltersMcp` is false and `_isActivatable(name)` returns false for any `mcp__*` tool with `direct` exposure, so a custom tool named `mcp__workspace__get_scanned_files` stays registered but is **never declared to the model**. Safe choices: omit `tools` and use `excludeTools`, or include `mcp__*` in `tools`, or avoid the `mcp__` prefix (then update every literal in H).
9. **Project trust.** `.pi/mcp.json`, `.pi/extensions`, `.pi/skills`, `.pi/settings.json`, `.pi/SYSTEM.md` load only after a trust decision; saved in `~/.pi/agent/trust.json`; `defaultProjectTrust` default `"ask"`; non-interactive modes skip protected resources unless `"always"` (security.md L36-90). `CLAUDE.md`/`AGENTS.md` context files load regardless of trust. Because the Acabox agent has Write and Bash on the workspace, a trusted `<workspace>/.pi` would let it self-provision MCP servers and executable extensions (same class as the `.mcp.json` hazard); PI also documents agents running `pi mcp add`/`pi mcp login` via bash (docs/cli.md L318-333), so the CLI must not be reachable on the agent PATH.
10. **Tool-call permission hooks** apply to MCP tools: `tool_call` handlers can `{block:true, reason}`; `pi.getAllTools()` exposes annotations (`readOnlyHint`, `destructiveHint`, ...). Acabox's two-layer `enabledTools` gate and the `document-reader` path guard map onto this.
11. PI's own MCP stdio spawn: env inheritance and lifetime facts are in E2.

## RISKS
- PI MCP rewrites tool names (mini-apps -> mini_apps). Every Claude-style literal (renderer useAssistantToolUI toolName, appChatLink OPEN_TOOL_NAMES, turnSteps OUTCOME_TOOLS, tool-card-display cases, omissionWatch connectorIdOfTool and RESERVED set, BUILTIN_TOOL_PATTERN, skills, KNOWLEDGE_ROUTING_GUIDANCE) breaks if the relays are registered as PI MCP servers; registering them as PI custom tools with unchanged names avoids this.
- PI treats any tool name starting with mcp__ as an MCP tool in its selection logic: with a non-empty createAgentSession tools allowlist lacking an mcp__ entry, direct custom tools named mcp__* are registered but never declared to the model (silent loss of all 12 relay tools). Must be pinned by a spike/test.
- PI default stdio transport inherits process.env, which in Acabox PI will include OpenAI/Anthropic/OpenRouter keys and ACABOX_API_TOKEN; hosted/authored/stdio-connector children would receive them unless createTransport forces inheritEnv:false or hosting stays in mcpHost.
- PI connects/closes MCP servers per session. If Acabox keeps destroying sessions after every turn, every turn re-handshakes all HTTP connectors (first prompt can wait up to startupWaitMs=10 s for direct servers) and PI-owned stdio children would be respawned each turn, losing server state.
- Agent self-provisioning: a trusted <workspace>/.pi directory can load .pi/mcp.json and .pi/extensions (executable code), and a reachable pi CLI allows `pi mcp add/login`. defaultProjectTrust must be forced to never, loadConfig must be host-owned, and the CLI must stay off the agent PATH. PI agent-dir token files (mcp-auth.json, auth.json) are plaintext 0600 JSON and not covered by the existing secret-read hook patterns.
- Secret fidelity/execution risk: PI interpolates $VAR/${VAR} and runs a leading ! as a shell command in MCP env/header values; unescaped Acabox-stored tokens containing $ or starting with ! would be corrupted or executed.
- SSE connectors have no PI equivalent (PI rejects sse); existing sse rows need a migration or an explicit refusal. stdio connectors exist in the type but not in the UI.
- No exported programmatic MCP connection-state accessor (McpServerConnection, signInMcpServer and McpOAuthCredentialStore are not exported); the Settings/Servers status vocabulary (connected/failed/needs-auth/pending/disabled/unknown) and sign-in button must be rebuilt on @earendil-works/pi-mcp or transport wrapping. Also unknown whether OAuth servers accept PI's default client name 'pi' (Claude CLI registered as Claude Code).
- Knowledge loop silently degrades under PI: collectKnowledgeSignals expects tool_use name 'Read' with input.file_path; PI's read tool is 'read' with 'path', so readPaths stays empty, every connector turn raises a connector-without-ledger review row and last_read is never bumped.
- Parallel tool execution: PI runs same-message tool calls in parallel by default. record_finding awaits the blast-radius grep between reading the ledger and appending when supersedes is set, so concurrent calls can race on the next finding id; needs executionMode 'sequential'. Hosted servers lose the per-server FIFO queue (concurrency 1) if executed through PI-managed MCP tools.
- Provider schema portability (multi-provider goal): call_published_tool.arguments is a free-form record, several tools take empty-object schemas, and hosted servers pass arbitrary JSON Schema ($ref/anyOf). Some providers (e.g. Gemini) reject such shapes; zod enums must become StringEnum. Needs a provider matrix test.
- Handlers depend on main-only resources (Electron Notification, better-sqlite3 built for the Electron ABI, safeStorage, WebContents). If PI runs in a child process the relay round trip must remain; if PI runs inside Electron main its bash subprocesses and agent loop share the main process.
- PI custom-tool results are not auto-truncated (PI truncates only its own MCP results at 20 KB). get_scanned_files, query_activity and read_chat (up to 120000 chars) are unbounded or large; INFERRED that Claude CLI's own MCP output cap may have masked this today.
- Hosted-server limitations to carry forward consciously: only the first tools/list page is read, tools/list_changed is ignored, effective call timeout is 60 s (not the documented 90 s), and non-text MCP content is dropped by hostedResultToRelayResult.
- Hosted tool names are not sanitised or length-limited by Acabox (jsonSchemaToZod path); a PI adapter must enforce the 64-char [A-Za-z0-9_-] provider limit and collision handling itself.
- Latent bugs/inconsistencies that will be copied if ported verbatim: MCP_AUTHENTICATE_TOOL regex is lowercase-only while connector ids may be mixed case; call_published_tool can emit text undefined; open_mini_application has no dir_name traversal check; query_activity/workspace descriptions are stale.
- Tests that will fail or become vacuous on the port: sidebarTabs.test.ts (pins two z.enum(SIDEBAR_TAB_IDS) files), agentAllowedTools.test.ts relay-presence assertions, agentServerHostedRelay.test.ts, jsonSchemaToZod.test.ts, and any test importing the Claude SDK.
