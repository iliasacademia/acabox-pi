## RISKS
- package.json fresh-install (line 28) and db:cobuilding:reset (line 21) will delete the ORIGINAL Acabox install, TCC grants and userData if copied unchanged into the PI repo.
- The new iliasacademia/acabox-pi repo is PUBLIC and empty while the checkout holds internal status (CLAUDE.md 242 KB), production-data findings under docs/design/review-2026-09-30, a dev token in .mcp.json, Cloudflare Access identifiers in share-workers wrangler.toml, and a CI file that references secrets; audit or make private before the first push.
- INFERRED: GitHub renames asset names containing spaces, so Forge artifacts named 'Acabox PI-darwin-arm64-X.zip' would make latest-mac.yml's url (written raw by generate-update-manifest.js:80) 404 in selfUpdater.ts:288; hyphenate in release.mjs and generate the manifest from the renamed file, or measure with a throwaway release.
- If PI_CODING_AGENT_DIR is not set on every PI-loading process, Acabox PI reads and writes ~/.pi/agent (auth.json with OAuth tokens and API keys, settings, models, sessions, skills, extensions), shared with the user's own pi CLI; ~/.pi already exists on this Mac.
- ChatGPT sign-in needs fixed loopback port 1455; concurrent Codex CLI, pi CLI, a second Acabox PI window or Acabox itself make login fail with PI's wording that mentions 'another pi session'; needs a plain-language port-busy state and the manual paste fallback.
- getDeviceId() falls back to fallback-<hostname> (utils/deviceId.ts:54-57), which is not a UUID, so Sign in with ChatGPT throws; the device id and agentName are also sent to OpenAI (agent_name_hint, ext_agent_host_id) and must be set deliberately.
- Provider API keys in the Electron process env (shell, .env.local) are spread into the agent Bash tool and mini-app exec children by buildSubprocessEnv (containerService.ts:104-115); the existing secret-read hook does not cover PI's auth.json or models.json, and hooks are a Claude Code mechanism that PI does not run.
- Policy and billing risk to confirm before shipping: third-party use of ChatGPT-plan tokens through the Sign in with ChatGPT token-sharing flow, and PI's Anthropic Claude Pro/Max OAuth (PI itself warns about paid extra usage, settings.md:173); recommend not surfacing Anthropic OAuth in v1.
- PI's own errors ('No API key found...', 'No models available', 'Use /login ...', docs paths) will reach the chat unless userFacingError and agentSession.isAuthError are extended; today's classifiers only know Anthropic wording.
- OAuth refresh-token rotation needs a single writer; splitting credentials between the host (safeStorage) and a PI process in the agent-server child can lose a rotated refresh token and force a re-login (INFERRED).
- PI sends anonymous install telemetry and a pi.dev version check by default (enableInstallTelemetry true); the product promises local-only research data, so PI_TELEMETRY=0 and PI_SKIP_VERSION_CHECK=1 must be set on every PI process.
- Dev builds share bundle id com.github.Electron (TCC, NSUserDefaults, Launch Services) with every other dev Electron app; keychain item name follows CFBundleName so forgetting rename-dev-electron.js reuses 'Electron Safe Storage'.
- Two apps with identical icons in one Dock and menu bar are indistinguishable; PI needs different art from gen-icons.mjs inputs.
- Renaming mini-app bridge globals, ab-* CSS, @acabox/jsx-edit or ACABOX_* constants would break exported tools moving between Acabox and Acabox PI; add aliases instead.
- The no-provider state does not exist today (no first-run nudge; a missing key only surfaces as a chat error); with several providers and OAuth this needs a first-run card, composer state and chrome chip.
- OpenRouter verification trap: /api/v1/models/user and /models return 200 with no key, so using them as a key check would report any key as valid; use /api/v1/key.
- OpenAI row semantics: PI keeps one credential per provider id, so ChatGPT plan and an OpenAI API key cannot both be stored under 'openai'; background and mini-app calls then follow whichever is active unless a second store is designed.
- Cost UI and DB assumptions are Claude-SDK-specific (cumulative total_cost_usd in result rows, Anthropic content-block JSON in messages used by history conversion, chat search and chat references); subscription auth makes dollar figures misleading.
- Env var names ACABOX_UPDATE_OWNER/REPO/TOKEN and ACABOX_RELEASE_REPO would redirect both apps from one shell export if not renamed; selfUpdater temp names collide if both update to one version concurrently.
- PI's published packages ship no LICENSE file and Acabox is UNLICENSED: the app must bundle MIT notices for @earendil-works/* and credit PI in the UI.
